# 个性化与呈现适配指南

用户提供既有格式、发送场景、Emoji要求或历史偏好时读取。格式服务于信息理解，不反过来限制事实。

## 1. 适配优先级

1. 用户本次明确要求；
2. 用户提供的现有模板；
3. 用户已经确认的稳定偏好；
4. 汇报对象、阅读设备、发送渠道和内容规模；
5. 简洁、中性的默认格式。

任何网站、应用、聊天工具、文档、移动端或PC端都可能成为使用场景。不要穷举平台，也不要根据平台名称机械套模板；理解用户说明的阅读方式、正式程度和排版能力。

## 2. 学习用户偏好

可以从以下信息中形成偏好：

- 用户明确说“以后都这样写”；
- 用户对生成稿进行的明确修改；
- 用户多次接受并沿用的稳定写法；
- 用户提供并声明要沿用的历史报告。

可学习的维度包括：

- 篇幅与信息颗粒度；
- 按项目、主题、状态或时间分组；
- 标题、日期、编号和空行；
- 语气、称谓、动词和禁用表达；
- 是否全部保留独立事项；
- 是否突出价值、风险、数据或下一步；
- Emoji、表格、Markdown等呈现偏好；
- 日报、周报、月报各自的固定习惯。

本次明确要求覆盖历史偏好。一次性要求不要自动升级为长期规则。调用方有持久记忆时，只保存抽象偏好并遵循其授权机制；不要把真实项目、数据或整篇报告作为偏好保存。没有持久记忆时，只在当前对话复用，不声称永久记住。

## 3. 结构选择

结构不是固定模板，可根据内容选择：

- 按业务、项目或职责模块；
- 按已完成、推进中、风险和下一步；
- 按目标、成果、问题和计划；
- 沿用用户自己的栏目。

内容较多且同一模块同时有完成和推进事项时，优先在模块内分状态，减少跨章节重复。内容很少时不要制造多层标题。

## 4. Emoji

Emoji只用于帮助扫读，不承担事实语义：

- `auto`：用户未指定且视觉提示确有助于阅读时少量使用；
- `on`：按用户指定风格使用；
- `off`：用户不需要、正式场景或现有模板不使用时关闭。

可使用“✅ 已完成、🚧 推进中、⏳ 待处理、⚠️ 风险”等组合，但它们只是示例，不是封闭状态列表。图标应配文字，保持一致，避免每句堆叠装饰。

## 5. 阅读与表达

- 重要事项按事实优先级靠前。
- 事项名称、结果或状态尽量在句首出现。
- 删除不影响理解的过程，保留交付、变化、范围、依赖和下一步。
- 移动端通常适合短段落和清晰空行；PC或结构化文档可以使用更完整的层级。用户指定其他方式时照其要求执行。
- 不以“一至两行”“30秒”等固定数字作为硬要求；目标是让目标读者以合理成本抓住重点。
- 默认输出正文；修改说明、覆盖映射和详细分析按需提供。

## 6. 价值反馈

用户需要复盘、表达“没做什么”或明确希望获得反馈时，可在正式正文之后单独增加简短说明：

- 概括本周期最主要的真实贡献；
- 指出其工作如何推动结果、降低不确定性或支持后续；
- 只使用输入中的事实，不使用空泛鼓励；
- 控制在一至三句话，避免影响正文复制。
