# Work Report Skill

一个事实优先、格式自适应的中文周期工作汇报 Skill。它把零散工作整理为真实、精简、状态清楚、价值明确且便于阅读的日报、周报、双周报、月报或阶段汇报。

## 它解决什么

- 从口语化记录生成可直接使用的工作汇报；
- 优化或审校已有汇报；
- 合并跨周期进展，减少重复并保留连续性；
- 检查遗漏、状态、时间、角色和价值是否准确；
- 按事实重要程度排序；
- 适配不同岗位、读者、渠道、设备和用户格式；
- 根据用户已确认偏好逐步形成个性化写法；
- 可选使用Emoji帮助扫读，并在正文外给予克制的价值复盘。

它不负责会议纪要、PRD、述职绩效、自动发送、网页或CLI，也不会为了“写得高级”而制造成果。

## 安装

把整个 `work-report` 文件夹复制到所用 Agent 的 Skills 目录，然后重新加载 Skills。也可以把本地文件夹交给支持安装 Skill 的 Agent，并要求其安装 `work-report`。

本 Skill 只有 Markdown、YAML 和 JSON 文件，无运行时依赖、无需密钥、无需联网，核心内容不依赖操作系统。具体 Skills 目录和重载方式以所用 Agent 宿主为准。

以 Codex 为例，可以复制到：

- Windows：`%USERPROFILE%\.codex\skills\work-report`
- macOS/Linux：`~/.codex/skills/work-report`

复制后重新加载 Skills，并发送下面的最短验证请求：

```text
使用 $work-report 整理周报：完成帮助文档发布；登录问题仍在排查。不要把排查中写成已解决。
```

安装成功时，输出应同时保留“文档已发布”和“问题排查中”，且不虚构解决结果。卸载时删除 Skills 目录下的 `work-report` 文件夹，再重新加载 Skills。

当前版本已于2026-08-24在 Windows 的 Codex Desktop 环境完成结构校验和独立行为试跑。其他宿主与操作系统的文本结构兼容，但尚未逐一实测；公开发布后应按真实结果更新兼容性说明。

## 使用示例

```text
使用 $work-report，把下面这些零散记录整理成本周周报。全部独立事项都要保留，适合手机阅读，可以使用状态Emoji。
```

```text
使用 $work-report，只检查这份月报有没有遗漏、重复、状态穿越或夸大价值，不要改写。
```

```text
使用 $work-report，结合上期周报和本期记录更新进度。沿用我之前确认的简短句式，不使用表格。
```

示例输出片段：

```text
✅ 帮助文档：已完成发布。

🚧 登录问题：当前仍在排查中。
```

## 个性化

当前明确要求优先于历史偏好。Skill可以利用调用方已经提供的对话、记忆、历史报告和用户修正，适配篇幅、语气、分组、标题、日期、Emoji、重点和常用表达。

Skill本身不建立账号或数据库，也不保证跨宿主持久记忆。调用方没有记忆能力时，只在当前对话中适配。

## 隐私

- 不主动上传、保存或发送用户报告；
- 不把真实姓名、项目、客户、数据或完整报告写入Skill；
- 用户标记为备注、仅供理解或不得输出的信息不会进入正文；
- 仓库中的评估案例必须完全虚构，而不是对真实报告做简单改名。

## 文件结构

```text
work-report/
├── SKILL.md
├── README.md
├── agents/openai.yaml
├── references/
│   ├── quality-guide.md
│   └── adaptation-guide.md
└── evals/
    ├── evals.json
    ├── trigger-evals.json
    └── RUBRIC.md
```

正常调用只加载 `SKILL.md`。复杂事实、跨期合并或审校时按需读取质量指南；有个性化和呈现要求时按需读取适配指南。README和评估资料不进入正常生成上下文。

## 评估原则

先证明没有改变事实，再评价表达质量。虚构、关键遗漏、误合并、状态穿越、角色升级或隐私泄漏属于失败，不能由“文案更好看”抵消。主观质量通过同模型、同输入的盲评比较，不由生成者自行打分。
